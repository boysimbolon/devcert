## Kenapa topik ini diuji
Soal I/O menanyakan metrik mana yang menunjukkan masalah dan di mana.

## Konsep inti
```sql
SELECT name, phyrds, phywrts, readtim, writetim, avgrdtm
  FROM v$filestat JOIN v$datafile USING (file#)
 ORDER BY phyrds DESC FETCH FIRST 10 ROWS ONLY;

SELECT * FROM v$iostat_file WHERE filetype_name='Data File'
 ORDER BY small_sync_read_latency DESC FETCH FIRST 10 ROWS ONLY;

SELECT event, average_wait, time_waited_micro/1e6
  FROM v$system_event
 WHERE event LIKE 'db file%read' ORDER BY time_waited_micro DESC;
```

Indikator: latency tinggi (ms per I/O), antrean panjang, satu file mendominasi.

## Jebakan
- Throughput tinggi belum tentu sehat bila latency juga tinggi.
- I/O tersebar bisa jadi masalah storage, bukan database.
- `db file scattered read` menandakan full scan berulang.
- Statistik V$FILE direset saat instance restart.

## Latihan
1. View untuk I/O per file?
2. Event mana yang menandakan full scan?
